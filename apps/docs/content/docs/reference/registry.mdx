---
title: Source registry
description: Install editable web and OpenTUI source from the hosted namespace or a Git tag.
---

The npm package family contains `whatsappd` and `@whatsappd/react`. Renderer components are source: the shadcn CLI copies them into the consumer’s repository.

Register the hosted namespace once in `components.json`:

```json
{
  "registries": {
    "@whatsappd": "https://aaronabuusama.github.io/whatsappd/r/{name}.json"
  }
}
```

```bash
# Hosted namespace
pnpm dlx shadcn@latest add @whatsappd/whatsappd
pnpm dlx shadcn@latest add @whatsappd/whatsapp-inbox
pnpm dlx shadcn@latest add @whatsappd/whatsapp-tui-inbox

# Reproducible Git tag (replace <tag> with a release that includes the registry)
pnpm dlx shadcn@latest add AaronAbuUsama/whatsappd/whatsapp-inbox#<tag>
```

The web catalogue also exposes `whatsapp-chat-list`, `whatsapp-conversation`,
`whatsapp-message`, `whatsapp-composer`, `whatsapp-account-state`, and
`whatsapp-operation-status` as individually installable source. The complete
`whatsapp-inbox` block composes those same files and accepts a
`WhatsAppBrowser` store; the consuming application keeps its routes,
authorization, media URLs, and theme tokens.

The OpenTUI catalogue exposes `whatsapp-tui-chat-list`,
`whatsapp-tui-conversation`, `whatsapp-tui-message`,
`whatsapp-tui-composer`, `whatsapp-tui-account-state`, and
`whatsapp-tui-operation-status`. The complete `whatsapp-tui-inbox` block owns
terminal focus, keyboard handling, layout, and scroll anchoring while consuming
the same renderer-neutral React store contract.

Pairing/onboarding is not published for either renderer yet because the working
examples have not proved protected QR challenge consumption. Both registry
addresses resolve canonical source at one package-family version; generated
`/r/*.json` files are build output, not committed source.
